# Synthetic Data Generation Rules

## 목적

Synthetic 데이터는 단순 난수표가 아니라, 분석했을 때 **제조 관점에서 해석할 수 있는 패턴**이 나타나도록 설계합니다.

다만 실제 공정조건이나 회사 데이터를 복원하지 않으며, 아래 규칙은 학습용 시나리오입니다.

---

## 1. 기본 규모

초기 버전:

- 약 800 Batch
- 6~12개월 수준의 생산기간
- 설비 3대
- 원료 LOT 여러 개
- OK / NG 비율은 지나치게 균형적이지 않게 구성

목표는 대용량 처리보다 **생산기술 분석 흐름을 검증할 정도의 데이터**를 만드는 것입니다.

---

## 2. 정상 변동

모든 값이 일정하면 분석할 이유가 없으므로 정상운전에서도 작은 변동을 부여합니다.

예:
- 온도: 기준값 주변의 작은 Random Noise
- 압력: 설비별 미세한 차이
- 원료물성: LOT별 평균 차이
- 품질값: 공정조건 + 측정 Noise

이 변동은 정상적인 공정 산포를 표현합니다.

---

## 3. 원료 LOT 효과

일부 원료 LOT는 평균 물성이 조금 다르게 생성됩니다.

예상되는 분석 결과:
- 특정 LOT에서 점도나 최종 품질의 평균이 약간 이동
- 단, 원료 LOT 하나만으로 모든 NG가 결정되지는 않음

목적:
- 원료효과와 공정효과를 함께 보는 연습

---

## 4. 설비 효과

설비 `EQ_A`, `EQ_B`, `EQ_C` 사이에 작은 Offset을 둡니다.

예:
- 특정 설비의 온도계측값이 조금 높은 방향
- 특정 설비에서 에너지 원단위가 조금 높음

중요:
- 설비 하나가 무조건 불량설비로 보이지 않도록 설정
- 다른 변수와 함께 볼 때 차이가 드러나게 설계

---

## 5. Time Drift

생산기간 후반으로 갈수록 일부 변수에 서서히 Drift를 발생시킵니다.

예:
- 반응시간의 점진적 증가
- 에너지 원단위의 완만한 상승
- 특정 설비의 변수 산포 증가

예상되는 분석:
- Rolling Mean
- 시계열 Plot
- 기간 전후 비교

목적:
- 단발성 이상치와 지속적인 공정 이동을 구분

---

## 6. 품질 영향 구조

`quality_flag`는 단일 변수 하나로 결정하지 않습니다.

예시 개념:

```text
Quality Risk
  = 공정조건 조합
  + 원료 LOT 효과
  + 설비 효과
  + 시간 Drift
  + Random Noise
```

예:
- 반응시간이 길고 특정 원료 특성이 함께 나타날 때 위험 증가
- 온도 또는 압력이 극단영역에 있을 때 위험 증가
- 설비 Offset은 단독으로는 약하지만 다른 조건과 결합할 때 영향

목적:
- 단순 threshold 찾기보다 다변량 분석과 모델링이 필요한 구조 만들기

---

## 7. 결측치와 이상치

현실적인 데이터 품질 문제를 재현하기 위해 소량의 결측치와 이상값을 포함합니다.

예:
- 일부 센서값 누락
- 품질측정값 미입력
- 비정상적으로 큰/작은 입력값

단, 이상값은 전체 데이터의 의미를 무너뜨릴 정도로 많이 넣지 않습니다.

목적:
- 분석 전에 Data Quality Check가 필요한 이유를 보여주기

---

## 8. 의도적으로 피할 것

다음과 같은 데이터는 만들지 않습니다.

- 변수 하나만 보면 품질판정이 100% 결정되는 데이터
- 모든 변수에서 OK / NG 차이가 명확한 데이터
- 실제 회사 공정조건을 추정할 수 있는 값
- 모델 정확도가 비현실적으로 100%에 가까운 데이터
- 분석 결과가 이미 정답처럼 보이는 데이터

---

## 9. 데이터 생성 후 검증

Synthetic 데이터 생성 후 다음 항목을 확인합니다.

1. 결측치 비율이 의도한 수준인지
2. OK / NG 비율이 과도하게 치우치지 않았는지
3. 특정 변수 하나만으로 품질이 결정되지 않는지
4. 설비·원료·시간 효과가 지나치게 강하지 않은지
5. PCA / Logistic Regression 등 후속 분석에서 해석 가능한 패턴이 존재하는지

이 검증을 통과한 데이터를 최종 분석용 버전으로 사용합니다.
