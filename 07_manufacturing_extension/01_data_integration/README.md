# 01. Data Integration & Quality Check

## 왜 먼저 데이터를 통합하는가

분석기법보다 먼저 확인해야 할 것은 **같은 Batch의 생산·원료·공정·품질 정보가 제대로 연결되어 있는가**입니다.

이번 단계에서는 4개의 합성 제조 데이터 테이블을 `batch_id` 기준으로 통합하고, 분석 전에 데이터 자체의 신뢰성을 점검했습니다.

```text
batch_master
material
process_condition
quality_result
      ↓
batch_id 기준 1:1 연결
      ↓
데이터 타입 확인
      ↓
결측 / 중복 / 통계적 이상치 점검
      ↓
통합 Master Table
```

실행 코드는 [integrate_and_validate.py](./integrate_and_validate.py)에 있습니다.

## 통합 결과

- 원본 테이블: **4개**
- 각 테이블: **800 Batch**
- 각 테이블의 중복 `batch_id`: **0건**
- 통합 후: **800행 × 19개 원본 변수**
- 품질판정: **OK 650건 / NG 150건**

즉, 테이블을 연결하는 과정에서 Batch가 사라지거나 중복으로 늘어나는 문제는 확인되지 않았습니다.

## 데이터 품질 점검 결과

핵심 분석변수에서 확인된 결측치는 총 **25개 셀**, 결측치가 하나 이상 포함된 Batch는 **24개**였습니다.

| 변수 | 결측치 |
|---|---:|
| raw_property | 4 |
| temperature | 8 |
| vacuum | 8 |
| viscosity | 5 |

결측치를 자동으로 평균값 등으로 채우지 않았습니다. 어떤 분석을 수행하는지에 따라 적절한 처리방법이 달라질 수 있기 때문입니다.

또한 IQR 기준으로 **61개 Batch**에서 하나 이상의 통계적 이상치 후보가 확인되었습니다.

여기서 통계적 이상치는 곧바로 오류를 의미하지 않습니다. 센서 문제일 수도 있고, 실제 공정의 특이상태일 수도 있으므로 **삭제 대신 REVIEW 표시**를 남겼습니다.

결측치 또는 IQR 이상치 중 하나라도 가진 Batch는 총 **83개**입니다.

상세 결과는 [DATA_QUALITY_REPORT.md](./DATA_QUALITY_REPORT.md)에 정리했습니다.

## 두 종류의 출력 데이터를 만든 이유

### integrated_master.csv

800개 Batch를 모두 유지한 통합 데이터입니다.

데이터 품질 문제를 숨기지 않고 다음 세 열을 추가했습니다.

- `dq_missing_count`: 해당 Batch의 결측치 개수
- `dq_outlier_count`: IQR 기준 이상치 후보 개수
- `dq_review_flag`: 사람이 한 번 더 확인할 필요가 있는지 표시

EDA에서는 이 데이터를 우선 사용합니다.

### analysis_ready_complete_cases.csv

PCA나 결측치를 허용하지 않는 모델에 바로 사용할 수 있도록 핵심 분석변수에 결측치가 없는 **776개 Batch**를 별도로 저장했습니다.

단, 통계적 이상치는 제거하지 않았습니다.

이상값을 먼저 지워버리면 실제 공정 이상징후까지 사라질 수 있기 때문입니다.

## 이 단계에서 내린 판단

> 데이터 품질 문제를 자동으로 수정하거나 제거하기보다, 원본을 보존하면서 분석자가 확인할 수 있는 플래그를 추가한다.

제조 데이터에서는 결측치나 극단값 자체가 설비·계측·운영 문제의 신호일 수 있습니다. 따라서 정제 과정에서 정보를 잃지 않는 방향을 선택했습니다.
